## Assistant

There are actually **two separate search systems** in the app. Since you've been asking about places/Discover, here's how the Discover page's search bar works, plus a note on the separate global search.

---

### Discover page search bar (`discover-screen.tsx`)

This is the search bar at the top of the Discover tab ("Search places, areas or vibes…").

**How it's wired:**
- The `SearchBar` is bound to `feed.query` / `feed.setQuery` from the `useDiscoverFeed` hook (`hooks/use-discover-feed.ts`).
- As you type, the query is **debounced 350ms** (`useDebouncedValue`) so it doesn't hit the API on every keystroke.
- Once the debounced query is non-empty, `isSearching` becomes `true` and the feed switches from "all places" to search mode.

**What happens under the hood (`services/places-service.ts`, `searchPlaces`):**
1. Trims the query.
2. **Resolves category synonyms** — it looks up the `category_synonyms` table and `place_categories` table (matching on `key` or `label` via `ilike`) so typing e.g. "restaurant" maps to the `food` category.
3. Builds a Supabase `.or()` filter across:
   - `name.ilike.%q%`
   - `area.ilike.%q%`
   - `address.ilike.%q%`
   - Plus `category.in.(<matched synonym keys>)` if any categories matched.
4. Selects place fields + `place_photos`, orders by `created_at DESC`, and paginates in pages of 20 (`PAGE_SIZE`).
5. Results come back through a TanStack Query **infinite query** (`useInfiniteQuery`), keyed on `['places', 'discover', 'search', debouncedQuery]`, so you can pull-to-refresh / load more (`fetchNextPage`).

**Client-side filtering on top:**
- If you're *not* searching but have a category chip selected, it filters the already-fetched places client-side by category.
- `savedOnly` similarly filters client-side to just your bookmarked places.

---

### Separate: Global Search Screen (`components/search/search-screen.tsx`)

There's also a full-screen/search-sheet search (summoned elsewhere in the app) that is **not** about places — it searches:
- **Listings** (`services/search-service.ts` → `searchListings`): searches `public.listings` across `title`, `location_landmark`, `city`, `campus`, plus layout-type enum matching (e.g. "self_contain", "single_room", "flat"). Debounced 300ms, min 2 chars.
- **Roommates** (`searchRoommates`): searches `public.profiles` across `full_name`, `username`, `school`, `bio`, filtered to onboarded users with `show_in_roommate_feed = true`, excluding yourself.

---

**Bottom line:** In the Discover search bar specifically, the method is a debounced Supabase `ilike` / `.or()` text search over place name, area, address, and resolved category — served as a paginated infinite list, with client-side category/saved filtering layered on top.
